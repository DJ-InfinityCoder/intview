1. Find the second highest salary from the Employee table.

SQL
SELECT MAX(salary) AS SecondHighestSalary
FROM employees
WHERE salary < (
    SELECT MAX(salary)
    FROM employees
);

Logic:

  1. The inner query finds the highest salary.
  2. WHERE salary < that value removes the top salary.
  3. MAX(salary) of the remaining rows is the second-highest distinct salary.
Concept

Subquery with an aggregate function.

Note

It returns NULL when there are fewer than two distinct salaries. Duplicate top salaries do not matter because the comparison is on the value.

2. Find duplicate records in a table.

SQL
SELECT name, COUNT(*)
FROM employees
GROUP BY name
HAVING COUNT(*) > 1;

Logic:

  1. GROUP BY name puts identical names in one group.
  2. COUNT(*) counts the rows in each group.
  3. HAVING COUNT(*) > 1 keeps only the groups that appear more than once.
Concept

Duplicate detection with GROUP BY and HAVING.

Note

Add more columns to GROUP BY to detect duplicates on a combination of columns (see Question 56).

3. Retrieve employees who earn more than their manager.

SQL
SELECT e.name AS Employee, e.salary, m.name AS Manager, m.salary AS ManagerSalary
FROM employees e
JOIN employees m ON e.manager_id = m.id
WHERE e.salary > m.salary;

Logic:

  1. Join employees to itself: e is the employee, m is the manager.
  2. e.manager_id = m.id links each employee to their manager's row.
  3. WHERE e.salary > m.salary keeps employees who earn more than their manager.
Concept

Self join.

Note

Employees without a manager (manager_id IS NULL) disappear because of the inner JOIN.

4. Count employees in each department having more than 5 employees.

SQL
SELECT department_id, COUNT(*) AS num_employees
FROM employees
GROUP BY department_id
HAVING COUNT(*) > 5;

Logic:

  1. GROUP BY department_id creates one group per department.
  2. COUNT(*) counts the employees in each group.
  3. HAVING COUNT(*) > 5 filters the groups after aggregation.
Concept

HAVING filters groups; WHERE filters rows.

5. Find employees who joined in the last 6 months.

SQL
SELECT *
FROM employees
WHERE join_date >= CURRENT_DATE - INTERVAL '6 months';

Logic:

  1. CURRENT_DATE - INTERVAL '6 months' computes the date six months ago.
  2. join_date >= that date keeps recent joiners.
Concept

Date arithmetic in WHERE.

Note

This is PostgreSQL syntax. MySQL: DATE_SUB(CURDATE(), INTERVAL 6 MONTH). SQL Server: DATEADD(month, -6, GETDATE()).

6. Get departments with no employees.

SQL
SELECT d.department_name
FROM departments d
LEFT JOIN employees e ON d.department_id = e.department_id
WHERE e.id IS NULL;

Logic:

  1. LEFT JOIN keeps every row from departments.
  2. Rows without a match have NULL in all employees columns.
  3. WHERE e.id IS NULL keeps only the departments rows that have no match in employees.
Concept

Anti-join to find parents without children.

Note

Always test a column that can never be NULL in a real match (usually the primary key) in the IS NULL check.

7. Write a query to find the median salary.

SQL
SELECT AVG(salary) AS median_salary
FROM (
    SELECT salary
    FROM employees
    ORDER BY salary
    LIMIT 2 - (SELECT COUNT(*) FROM employees) % 2
    OFFSET (SELECT (COUNT(*) - 1) / 2 FROM employees)
) AS median_subquery;

Logic:

  1. Count the rows (N). The middle position is (N - 1) / 2 (integer division), used as the OFFSET.
  2. LIMIT 2 - N % 2 fetches 1 row when N is odd and 2 rows when N is even.
  3. AVG(salary) of those one or two middle rows is the median.
Concept

Median using ORDER BY, LIMIT and OFFSET.

Important

Subqueries inside LIMIT/OFFSET work in PostgreSQL but not in MySQL. The simpler PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY salary) (Question 153) is usually preferred.

8. Running total of salaries by department.

SQL
SELECT name, department_id, salary,
    SUM(salary) OVER (PARTITION BY department_id ORDER BY id) AS running_total
FROM employees;

Logic:

  1. PARTITION BY department_id restarts the total for each department.
  2. ORDER BY id defines the order in which rows are added.
  3. SUM(salary) OVER (...) adds salaries from the first row up to the current row.
Concept

Running total with SUM() OVER.

Note

With only ORDER BY, the default frame is RANGE, so rows with equal id values share one total. Add ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW for a strict row-by-row total.

9. Find the longest consecutive streak of daily logins for each user.

SQL
WITH login_dates AS (
    SELECT user_id, login_date,
        login_date - INTERVAL ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) DAY AS grp
    FROM user_logins
)
SELECT user_id, COUNT(*) AS streak_length, MIN(login_date) AS start_date,
    MAX(login_date) AS end_date
FROM login_dates
GROUP BY user_id, grp
ORDER BY streak_length DESC;

Logic:

  1. ROW_NUMBER() numbers each user's login dates in order.
  2. Subtracting that number of days from the date gives the same value (grp) for every date in an unbroken streak.
  3. Group by user_id and grp; COUNT(*) is the streak length and MIN/MAX give its start and end.
Concept

Gaps and islands technique.

Important

The INTERVAL ROW_NUMBER() OVER (...) DAY syntax is MySQL-style and varies by database. The query also lists every streak for each user, and duplicate login dates would break the numbering. The PostgreSQL version below removes duplicate dates and keeps only each user's longest streak.

PostgreSQL version returning only the longest streak per user:

SQL
WITH login_dates AS (
    SELECT DISTINCT user_id, login_date
    FROM user_logins
), grouped AS (
    SELECT user_id, login_date,
        login_date - (ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date))::int AS grp
    FROM login_dates
), streaks AS (
    SELECT user_id, COUNT(*) AS streak_length,
        MIN(login_date) AS start_date, MAX(login_date) AS end_date,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY COUNT(*) DESC) AS rn
    FROM grouped
    GROUP BY user_id, grp
)
SELECT user_id, streak_length, start_date, end_date
FROM streaks
WHERE rn = 1;

10. Recursive query to find the full reporting chain for each employee.

SQL
WITH RECURSIVE reporting_chain AS (
    SELECT id, name, manager_id, 1 AS level
    FROM employees
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.id, e.name, e.manager_id, rc.level + 1
    FROM employees e
    JOIN reporting_chain rc ON e.manager_id = rc.id
)
SELECT * FROM reporting_chain ORDER BY level, id;

Logic:

  1. The anchor query starts with the top employee (manager_id IS NULL) at level 1.
  2. The recursive part joins employees to the rows already found through manager_id = rc.id, adding 1 to the level each time.
  3. Recursion stops when no more employees are found; the final query orders by level.

Showing the chain as text:

SQL
WITH RECURSIVE chain AS (
    SELECT id, name, manager_id, name::text AS path
    FROM employees
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.id, e.name, e.manager_id, c.path || ' > ' || e.name
    FROM employees e
    JOIN chain c ON e.manager_id = c.id
)
SELECT name, path
FROM chain
ORDER BY path;
Concept

Recursive CTE for hierarchies.

Note

This returns each employee's level in the hierarchy. To display the actual chain (CEO > Manager > Employee), carry a text path through the recursion.

11. Write a query to find gaps in a sequence of numbers

SQL
(missing IDs).
SELECT (id + 1) AS missing_id
FROM employees e1
WHERE NOT EXISTS (
    SELECT 1 FROM employees e2 WHERE e2.id = e1.id + 1
)
ORDER BY missing_id;

Logic:

  1. For each id, check whether a row with id + 1 exists.
  2. NOT EXISTS is true when the next number is missing.
  3. id + 1 is reported as the missing ID.
Concept

Gap detection using NOT EXISTS.

Important

The highest ID always qualifies, so max(id) + 1 is reported even though it is not a real gap. Exclude it as shown below.

Corrected version that ignores the last ID:

SQL
SELECT (e1.id + 1) AS missing_id
FROM employees e1
WHERE NOT EXISTS (
    SELECT 1 FROM employees e2 WHERE e2.id = e1.id + 1
)
AND e1.id < (SELECT MAX(id) FROM employees)
ORDER BY missing_id;

12. Calculate cumulative distribution (CDF) of salaries.

SQL
SELECT name, salary, CUME_DIST() OVER (ORDER BY salary) AS salary_cdf
FROM employees;

Logic:

  1. ORDER BY salary sorts employees from lowest to highest salary.
  2. CUME_DIST() returns the fraction of rows with a salary less than or equal to the current salary.
Concept

Cumulative distribution window function.

Note

Values range from just above 0 up to 1. Employees with equal salaries share the same value.

13. Compare two tables and find rows with differences in any column (all columns).

SQL
SELECT *
FROM table1 t1
FULL OUTER JOIN table2 t2 ON t1.id = t2.id
WHERE t1.col1 IS DISTINCT FROM t2.col1
    OR t1.col2 IS DISTINCT FROM t2.col2
    OR t1.col3 IS DISTINCT FROM t2.col3;

Logic:

  1. FULL OUTER JOIN keeps rows that exist in only one of the tables.
  2. IS DISTINCT FROM compares values and treats NULL as a normal value (two NULLs are equal).
  3. Any column difference, or a missing row on either side, makes the row appear in the result.

41. Write a query to detect circular references in employee-manager hierarchy (cycles).

SQL

    SELECT id, manager_id, ARRAY[id]
    FROM employees
    WHERE manager_id IS NOT NULL
    UNION ALL
    SELECT e.id, e.manager_id, path || e.id
    FROM employees e
    JOIN mgr_path mp ON e.manager_id = mp.id
    WHERE NOT e.id = ANY(path)
)

FROM mgr_path
WHERE id = ANY(path);

  1. The query below walks upward from each employee through manager_id, remembering where it started.
  2. If the walk returns to the starting employee, that employee is part of a loop.

Important

Corrected cycle detection:

    SELECT id AS start_id, manager_id AS current_id, 1 AS steps
    FROM employees
    WHERE manager_id IS NOT NULL
    UNION ALL
    SELECT w.start_id, e.manager_id, w.steps + 1
    FROM walk w
    JOIN employees e ON e.id = w.current_id
    WHERE e.manager_id IS NOT NULL
        AND w.current_id <> w.start_id
        AND w.steps < (SELECT COUNT(*) FROM employees)
)
SELECT DISTINCT start_id AS employee_id
FROM walk
WHERE current_id = start_id;

266. Calculate the retention rate of customers month-over-month.

    SELECT customer_id, DATE_TRUNC('month', order_date) AS month
    FROM orders
    GROUP BY customer_id, month
), retention AS (
    SELECT current.month AS current_month, current.customer_id
    FROM monthly_customers current
    JOIN monthly_customers previous ON current.customer_id = previous.customer_id
        AND current.month = previous.month + INTERVAL '1 month'
)

    COUNT(DISTINCT customer_id) * 100.0 / (SELECT COUNT(DISTINCT customer_id)
    FROM monthly_customers WHERE month = current_month - INTERVAL '1 month') AS retention_rate
FROM retention
GROUP BY current_month
ORDER BY current_month;

    FROM orders

FROM monthly_customers p
LEFT JOIN monthly_customers c
    ON c.customer_id = p.customer_id
    AND c.month = p.month + INTERVAL '1 month'
GROUP BY p.month
ORDER BY month;

Joining on salary repeats rows when several employees share a salary, because the ranking CTE has one row per employee. Calculate the rank directly on employees instead.

Simpler version:

SQL
SELECT *
FROM (
    SELECT e.*, PERCENT_RANK() OVER (ORDER BY salary DESC) AS pr
    FROM employees e
) t
WHERE pr <= 0.05;

335. List departments with no open positions.

SQL
SELECT d.department_id
FROM departments d
LEFT JOIN job_openings j ON d.department_id = j.department_id AND j.status = 'Open'
WHERE j.job_id IS NULL;

Logic:

  1. LEFT JOIN keeps every row from departments.
  2. Rows without a match have NULL in all job_openings columns.
  3. WHERE j.job_id IS NULL keeps only the departments rows that have no match in job_openings.
Concept

Anti-join with a condition in ON.

Important

j.status = 'Open' must stay in the ON clause. In WHERE it would remove the NULL rows.
